# 不可反压入口与CDC：实现与验证合同

2026-11-04，已实现`af_rx_ingress`与`af_receive_pipeline`；10bin组合RTL与布线后功能网表完成4096包/81920字比较，125MHz ROUTED时序通过。RFSoC仅提供测试帧，不开发其硬件。路径为：真实CMAC原生AXIS RX → 整包准入/暂存 → 异步FIFO → parser/ring/RAM → 测试消费者。**完整payload比对使用CMAC边界激励**；真实CMAC已加入SYNTH/ROUTED，但真实双端CMAC/GT串行peer仿真226930实例，当前XSim BASIC限50000，仿真引擎未启动。两类证据不能合并为完整链路SIM PASS。各源hash及报告见[当前执行记录](../reports/phase2-cx-m3.zh-CN.md)。

## 缓存分工

入口FIFO吸收两个时钟域的差异、parser处理包头/准入时的停顿和有界突发；raw ring负责256源按时间窗对齐及等待消费者。两者分别计容量与读写带宽。不能用更深FIFO弥补长期pps超载，也不能把消费者停顿直接换成同样长的入口停顿而不分析ring能否继续收包。

使用当前Vivado随附的`xpm_fifo_async`，数据与完整包描述符分离。FIFO按最大允许帧预留空间，包尾经过一级寄存后发布描述符，消费者只读取已完整接收的包。坏包用丢弃描述符回收已写数据；未准入的包在RX域排空，不产生半包。XPM的存在不能代替RTL、时序、CDC及bus-skew检查。

当前数据FIFO为4096个577bit条目（data512、keep64、last1），对应256KiB原始数据容量，keep/last另占空间；错误状态转换成丢弃描述符，不必逐拍存error。独立实现实际64.5块BRAM36等效；非同等大小的科学有效负载。满帧9014B，每次按141个64B条目加4个流水/计数安全条目准入。还预留描述符流水余量，不能只看数据FIFO容量。

真实CMAC组合综合揭示`TKEEP`到包长/坏包计数的路径较长，已在RX域增加一级data/keep/valid/last/error及字节数/keep检查寄存器，状态机使用这一拍后的信号。RX仍无ready；最大帧预留的流水余量保留。新版独立默认容量和10/12bin组合RTL已重测，旧版独立入口时序数字不能沿用到新版。

64项描述符在256源100Gbps集中到包测试中先满，诊断运行拒收92包。当前组合配置明确用256项描述符（模块默认值仍为64，实例参数覆盖）；相同burst测试4096包/81920数据字通过，数据峰值3384/4096字。该结果只支持指定包长、节奏和消费合同，不保证任意突发。

同样125MHz、T8、5槽、4096数据项/256描述符、20µs消费者停顿：12bin RTL通过4096包/98304字，入口峰值3833；13bin第一组burst发生3包空间拒收，无损测试失败。12bin raw ring综合占64个URAM，已用满器件URAM；13bin若仍用5槽需33280个512bit字，按当前72bit×4096深银行组织将需72个URAM，尚未综合该点。以上是当前架构与输入合同的局部边界，不是芯片通用极限。

当前12bin布局的精确账本（字节均为8bit，KiB/MiB采用1024进位）：

| 部分 | 逻辑容量 | 实际分配/用途 |
|---|---|---|
| 输入FIFO的512bit数据 | 4096×64B＝256KiB | 含网络/AFP1报头及总线尾部空位，不能全部称科学电压容量 |
| keep/last | 4096×65bit＝32.5KiB | 与数据一起跨域；577bit总计288.5KiB |
| 输入FIFO实际BRAM | 64个RAMB36＋1个RAMB18＝64.5块BRAM36等效，290.25KiB物理位数 | routed层级报告确认全部属于ingress/data_fifo；不是新增科学ring空间 |

实际分配依据`cx-p2_11-shell-20261104-04/reports/utilization_hier_impl_1.rpt`（snapshot hash见执行报告）；上述银行解释为由布局尺寸推导，资源数量以该routed报告为准。当前每个raw store端口512bit×125MHz的理论上限是64Gb/s，读写各一个端口，同地址冲突串行。它不是64Gb/s科学处理通过结论：parser/事务周期、包头开销和消费者反压都降低有效吞吐。已验证输入合同为名义30.72Gb/s科学数据、2.5Mpps、含帧开销33.32Gb/s，瞬时burst按100Gb/s。加深缓存不能弥补长期平均服务不足；当前不依赖DDR，DDR带宽没有被验证。

## 必须验证的事务规则

1. RX无ready。第一拍决定准入：数据空间和描述符空间同时预留；后续不得因消费反压停止RX。
2. 保留数据/keep/last/error，或以明确坏包描述符丢弃；接收错误、超长、缺尾超时及资源不足分别统计。超长/缺尾后排到真实last再同步。
3. 完整描述符发布前，不向parser输出该帧任何拍；发布后，输出在ready=0时保持稳定。过载丢整包，不能只吞掉中间拍。
4. 数据和描述符FIFO跨域延迟可能不同，消费端必须等待数据实际可读，不以描述符到达保证数据已经到达。FIFO下溢/上溢必须始终为零，协议违规另报错。
5. FIFO reset同步到RX写域；处理域使用独立XPM异步置位/同步释放复位，禁止原始RX复位直接参与处理域使能。独立入口要求复位保持至少16个RX周期、两个时钟持续运行。组合配置握手后以toggle/ack请求RX域保持32周期复位；导出复位是单个寄存器电平，不能由多bit计数器组合译码直接驱动。等待两侧reset-busy结束，内部prime解析器后才置ready_for_data；RX同时排到真实last恢复帧边界。
6. RX统计按每次入口reset计数，core统计按其既定reset规则计数；两者不能跨配置直接相减。稳定且已排空时：rx_started=rx_queued+rx_bad+rx_no_space，m_delivered=rx_queued，m_discarded=rx_bad。运行中另有一个准入包、流水描述符和FIFO驻留；reset中断/初始resync另列，不能假装完整交付。RX统计保留RX时钟域属性，未直接跨域作为控制寄存器读取。

## 测试与实现门槛

- 独立不相关RX/处理时钟，覆盖相位变化、频率差和两域复位；先确认CMAC实际输出时钟，不能用处理时钟代替。
- 额定paced流量、接近线速突发、背靠背帧、短包/keep错误、末拍错误、缺尾/超长、FIFO满、下游长停顿与恢复，逐字节独立比较。
- 合并真实接收核重放乱序、重复、截止、epoch、槽复用、20us消费者停顿；报告入口及ring峰值、丢包原因、实际pps与有效科学带宽。
- 真实XPM/CMAC综合，报告FIFO RAM成本、CDC与复位路径、时钟及例外约束；不能设置笼统false_path掩盖同域路径。CMAC GT/时钟位置需有依据，未证实的板级连接仍为NOT VERIFIED。

最终验收要区分最高通过负荷和相邻失败负荷，消费者是测试模型，科学核属于M4，不在本轮实现。

配置中途切换测试已通过：旧配置下保留回复反压、一个已提交source255、一个排队重复及source0半包；切换后清理旧上下文，拒收旧epoch帧，完整读取新代次20字，旧代次done不释放新槽。该测试使用手动时间标签验证语义，不是速率测试。

持续负荷另有`cx-p2_06-pipeline-20261104-13`：同12bin/T8/125MHz接收RTL，128块32768包/786432字通过，消费者每8块停20µs，共16个完整停顿窗，入口峰值仍3833字。长测曾发现测试台在第22块把ps整数乘法溢出为负时间，已以单调性检查复现并在乘法前转实数修复；原错误激励构建`pipeline-10/11/12`保留但不用于硬件容量结论。详见执行报告和各自source_snapshot。
