# 第二阶段中间结果：接收模块首轮实际构建

2026-11-03，**执行中，第二阶段尚未完成**。本批使用 Vivado 2026.1 MCP，器件 `xcku5p-ffvb676-1-i`。没有上板操作。

大白话：现在确实写了电路、跑了综合和布局布线。先做了“检查包头”和“存放原始数据”两个零件；还没有把它们接成能收真实网络包的完整接收器。两档完整数据容量均能映射进 KU5P 的片内 URAM，存储内部时序达到 250MHz；但需要的控制、入口、转置和算法资源还没加进去，不能据此宣布 128 张卡方案成立。

## 已执行的结果

下表资源为 routed 结果；SYNTH 与 ROUTED 分别保存在[机器可读记录](phase2-progress.json)。WNS 正数表示当前约束下内部建立时序有余量，负数表示失败。

| 独立模块 | 功能仿真 | routed LUT / FF / DSP / URAM | 250MHz WNS / WHS |
|---|---|---|---|
| 对齐 AFP1 报头检查 | 20例，39周期，15拍输出停顿检查通过 | 409 / 1260 / 8 / 0 | **−2.288ns** / +0.050ns，建立时序失败 |
| mapped128 原始数据存储 | 25600个512bit字全量读写；RTL及布局布线后网表均通过 | 13 / 514 / 0 / 56 | **+0.345ns** / +0.114ns |
| candidate128 原始数据存储 | 28672个512bit字全量读写；RTL及布局布线后网表均通过 | 13 / 514 / 0 / 56 | **+0.361ns** / +0.077ns |

两档存储均为零 BRAM；全部模块的内部无时钟/未约束端点数为零。存储 TNS/THS 为零、route error 为零、DRC checks found 为零。单时钟模块的 CDC 报告不证明将来 CMAC 与处理域的跨域正确性。外部 IO 无板级时延约束，OOC 的 `HD.CLK_SRC` 未指定，结果仅支持当前内部路径；不是板级 250MHz 接口认证。

报头初版的关键路径是 ADC 时间映射乘加/比较。对**同一份已布线网表**重新检查时钟：200MHz WNS −1.288ns；125MHz WNS +1.712ns。这是时序重分析，没有分别重新实施两次布局布线，也不是芯片全局最高频率。下一轮将分拆该运算流水。

## 缓存获得的实际信息

- mapped128：10槽 × 256源 × 640B = **1.5625MiB** 数据。
- candidate128：7槽 × 256源 × 1024B = **1.7500MiB** 数据。
- 两档实际均用 **56/64 URAM，87.5%**。按块的物理总位数为1.96875MiB；宽度和深度取整使较小的 mapped 配置未减少 URAM 块数。其余8个URAM和480个BRAM尚需承载系数、暂存、工作区等，不能直接视为整卡余量。
- mapped测试含2183次同地址冲突、9921拍输出停顿；candidate为2445次、11112拍。读阶段分别37110/41564周期，包含人为施加的停顿。这不是网络可持续Gb/s，也尚未验证第一阶段100Gb/s消费者合同。

当前存储只有读写与冲突串行化，不管理槽归属、generation、pending/committed bitmap、deadline或包尾提交。复位不清 RAM，后续必须靠有效掩码防止旧数据成为科学贡献。完整 ring buffer 仍是首要后续工作。

## 保留的失败与限制

1. 第一次报头构建的 OOC 属性拼写错误，生成了板级 I/O buffer；已停止该次实现，保留目录，修正脚本后用新目录重跑。新收集流程会检查实际 I/O buffer，防止再次误记 OOC 结果。
2. 存储最初的网表仿真在第1号字失败。测试在20ns开始初始化，落在默认100ns全局复位内；改为140ns后，RTL不变，两档完整 routed 网表仿真均通过。该启动要求见[AMD UG900](https://docs.amd.com/r/2023.2-English/ug900-vivado-logic-simulation/Using-Test-Benches-and-Stimulus-Files)。原测试快照及最初综合后失败日志留在外部目录。
3. 网表仿真仍有 URAM 级联未使用输入端口告警，原日志保留，未静默；完整地址空间逐字比较通过，routed DRC无违规。后续改 RAM 布局时必须重做网表比较，不能只沿用本次时序数字。
4. CMAC实际IP综合因缺少 `cmac_usplus@2020.05` 授权失败；KU11P/KU15P/ZU47DR没有安装器件库。用户决定先做独立模块。完整CMAC shell与替代器件对比保持 **NOT VERIFIED**，板级保持 **NOT RUN**。
