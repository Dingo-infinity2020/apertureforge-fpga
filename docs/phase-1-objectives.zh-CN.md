# 第一阶段任务目标：RFSoC 分频分发与 KU5P 接收缓存

日期：2026-11-03。阶段编号 P1，对应优先工作包 AF-000。

当前状态：**离线阶段完成**。输入/包格式、256源网络及全目的地接收槽、512块轨迹、包长对照、缓存比较与阶段决策均已验收。证据范围与后续硬件边界见 [逐项审计](phase1-acceptance-audit.zh-CN.md)、[决策报告](../reports/phase1-decision.zh-CN.md)。下方保留原任务要求。

## 总目标

为 1024 个双极化天线建立可复现的离线数据通路模型，确定 RFSoC 如何将频道化电压分发到单口 KU5P，以及 KU5P 如何在有限缓存和明确截止时间内对齐 256 个源的数据。

阶段结束必须给出：**推荐发包格式和调度、KU5P 接收槽设计、缓存/DDR 预算，以及考虑包开销与有界抖动后的每片接入能力**。这些结论带有明确假设，用于指导下一阶段接收 RTL 与算法核综合，不称为硬件实测上限。

## 基准与边界

| 项目 | 第一阶段采用的范围 |
|---|---|
| 输入规模 | 1024 个物理天线、双极化，共 2048 路；256 个 RFSoC 源，每源 8 路 |
| 主带宽 | 200 MHz；500 MHz 做扩展预算及边界检查 |
| 输送精度 | PFB 后 I/Q 各 8 bit；科学带宽与实际输出采样率分别记账 |
| 接收硬件 | 现有 FNIC-KU5P、一个独立 100G 口；不计第二 QSFP 的额外带宽 |
| 时间频道化 | 先用 4096 个保留信道的理想基准；同时核对 320 MS/s、4096 点 FFT、保留 2560 bin 的实际可映射情形 |
| 发包块 | 200 MHz 优先比较 T=2/4，T=1/8 作边界对照；500 MHz 比较 T=4/8 |
| 差分抖动窗口 | 扫描 10/100/1000 µs；100 µs 是初始设计目标，不是已测网络保证 |
| 下游处理 | 用可配置吞吐与最大停顿的服务模型，暂不实现完整波束/FFTT/EPIC |
| 验证方式 | 资料审计、解析计算、离散事件仿真、小规模逐样本参考对比 |

## 任务与交付

### P1-01：冻结输入与硬件预算

- 核对 FPGA 料号、单口 CMAC/GT 路径、片内 RAM、DDR 接线/ECC、可重建 MIG 参数线索。
- 分清 RF-ADC 采样率、DDC 输出率、PFB 总 bin、保留 bin、科学带宽、过采样与量化位宽。
- 给 RFSoC 的 PFB/FFT、组包和网络分别列出吞吐需求；未知的资源占用、MIG 速率和 DDR 效率明确列为待综合/待测项。

**交付**：`docs/input-and-hardware-contract.zh-CN.md` 及机器可读基准配置。

**验收**：每个预算参数可追溯到资料、推导或标记的假设；前端、全阵列、逐频率分片三种数据率计算相符。不能把现有 I/Q16 时域固件当作已实现的新 F-engine。

### P1-02：冻结数据包与频率分片契约

- 定义 source→天线/极化映射、频率组→目的节点映射，以及非整除末组。
- 定义版本、epoch/config、首时刻标签、频率起点/数量、时刻数、数据类型与有效性。
- 规定 I/Q 符号、字节序、时间/频率/本地输入的排列、时间标签到 ADC/PFB 时刻的对应关系。
- 定义配置切换、分片异常与错误长度的处理；新协议采用版本管理，不能默认为旧 RFSoC 固件的实际线格式。

**交付**：`docs/packet-contract-v1.zh-CN.md`、频率路由表生成器及确定性编码/解码向量。

**验收**：正常情况每个 `(epoch, time, frequency, antenna, polarization)` 样本恰好分配一次；无重复、无遗漏、无错误极化和频率顺序，全部报文满足声明 MTU。

### P1-03：建立 RFSoC 发包与交换队列模型

- 模拟 RFSoC 组包等待、有限组包区和 100G 出口序列化。
- 对比同序突发、目的顺序旋转、源相位错开和 pacing。
- 先采用参数化的交换输出队列与链路服务模型，明确其拓扑/缓冲假设，不替未知交换机虚构实测能力。
- 统计源端 pps/带宽/排队、目的端 pps/带宽、峰值队列和源间到达偏差，验证是否存在长期队列增长。
- 先用小规模逐包真值对比；扩展到 256 源时可用事件/标签级数据表示，但须保留源出口和目的入口的真实序列化约束。

**交付**：`scripts/simulate-corner-turn.mjs`、参数场景与 `reports/phase1-transport.*`。

**验收**：模型再现已有解析包率和线占用；能识别持续超载与同步 incast；给出至少一套 200 MHz 候选调度在声明服务/抖动界限内的稳定队列结果。若 74 节点方案不满足，就降低每节点信道数并明确更新规模，不能依靠无限队列使其通过。

### P1-04：建立 KU5P 时间环形槽参考模型

- 按 `(epoch, frequency_group, absolute_time_block)` 寻址，槽中保留 generation 标签及源有效 bitmap。
- 定义到齐提前释放、截止释放、重复拒收、迟到拒收、超前包、窗口已满和 epoch 切换。
- 分别建模源端组包等待、差分抖动、接收处理和下游最大停顿，推导整块取整后的槽数；不将目前假定的两个 guard block 当作已证明的最小值。
- 保留无效输入掩码、贡献权重/有效数和丢失原因，按固定时间窗输出。

**交付**：`models/receive-ring.mjs`、可复现故障场景、槽深度/时延/峰值占用报告。

**验收**：声明的无丢包输入和负载界限内，无模型自身造成的意外丢失；注入重复、乱序、缺失、迟到、跨 epoch、回绕和反压后，无串窗、无旧包覆盖新槽、无重复贡献、无无限等待。拒收和缺失均能记账；到达/拒收/消费/驻留的计数按统一口径守恒。

### P1-05：比较缓存架构与 DDR 需求

- 比较原始电压环形槽、到包即做线性累加、片内短窗口加 DDR 扩展。
- 对线性累加先以小规模宽位整数波束加和验证乱序等价性；这里不实现全部科学算法。非线性舍入/饱和和权重切换单独检查。
- 分开列出数据区、bitmap/标签、工作槽、读写并发、算法预留空间和源端组包缓存。
- 计算 DDR 有效写加读需求及访问形态，列出必须在下一阶段验证的 MIG 吞吐条件。

**交付**：`reports/phase1-buffer-comparison.md`，至少包含峰值容量、读写带宽、时延和适用条件的比较表。

**验收**：给出推荐方案及淘汰理由；不采用“全部片内 RAM 都可给 ring”或“DDR 芯片额定速率就是实测效率”的假设。若只能在更低每片负载下成立，明确给出该负载；未知 DDR 性能作为条件，不标记为硬件通过。

### P1-06：形成第一阶段决策报告

- 选择 200 MHz 的包布局、T、调度、接收窗口、槽结构和错误策略。
- 给出单片接收科学带宽/信道数与缓存条件，并据此重算网络处理节点数量；与“74 片入口下限”对照解释差异。
- 对 500 MHz 给出同一设计能否扩展、所需 pps/缓存及尚未解决的条件。
- 明确哪些瓶颈在 RFSoC、交换队列、KU5P 解包/重排、DDR 或下游服务；暂不把算法核峰值当作端到端能力。

**交付**：`reports/phase1-decision.zh-CN.md`，附复现命令、配置、随机种子/确定性场景、源版本、结果及下一阶段接口要求。

**验收**：能根据报告直接编写接收器 RTL 任务，且所有候选结论明确区分解析、仿真与待硬件验证；未解决的科学/硬件参数有负责人待办或明确验证入口，不以无依据的默认值隐去。

## 执行顺序与完成判据

依次完成 P1-01 → P1-02 → P1-03/P1-04 → P1-05 → P1-06。P1-03 与 P1-04 共用协议和时间契约；只有各自参考模型检查通过后才联接。

第一阶段完成要求：

- [x] 输入、时间、频率、包格式和配置切换契约已版本化。
- [x] 256 源发包/交换/接收模型可一条命令复现，并有小规模独立真值对照。
- [x] 所选 200 MHz 候选在声明负荷、抖动和下游停顿界限内无持续队列增长及意外损失。
- [x] 故障注入无串窗、无重复贡献，全部损失和拒收可追溯。
- [x] 推荐缓存方案有容量、端口/带宽、释放期限和 DDR 前提，不依赖无界存储。
- [x] 决策报告给出每片接入能力的条件，以及接收 RTL/DDR/算法综合的下一步清单。

本阶段不启动 FPGA 编程、真实高速发包、驱动/系统配置、全量算法实现或硬件 DDR 压测。第一阶段通过代表**离线架构与接收契约通过**；RFSoC F-engine 时序、KU5P full-shell 时序、实际 DDR 和交换网络性能必须在后续阶段分别验收。
